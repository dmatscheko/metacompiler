# message which rows moved and why.
#
# recorded at commit a3164ff, in a clean `git archive` tree, at 9 DRAWS per row.
#
# ONE ROW MOVED AND IT MOVED ON PURPOSE: ruby 6,382,412,819 -> 5,629,804,567,
# -11.8% against its own 3.9% spread, from a3164ff. Ruby gained arbitrary-
# precision Integers and got FASTER, because the two `typeof`s that decide
# whether an operand is a bignum also answer rbToF and rbNumRank without calling
# them - removing four MetaJS calls per arithmetic step that the OLD code was
# already paying. (The first draft of that work was +38.79%; see the commit.)
#
# Every other row is inside its own spread. Note lua at +2.04% against a 2.05%
# spread with NO lua change in the round: that is the layout lottery sitting
# exactly on the line, and it is recorded rather than smoothed so the next
# person knows this row is the noisiest relative to its own size.
#
# WHY A MEDIAN OVER DRAWS AND NOT A NUMBER. A binary's instruction count depends on
# its CODE LAYOUT, and layout is perturbed by things that change no semantics. One
# unchanged kotlin source, varying only the length of the -exe output path:
#
#   17.353 17.494 17.620 17.911 17.915 17.916 17.916 18.018 18.023 18.182 G
#
# 4.8%, bimodal, from a file NAME. A module edit draws from the same distribution,
# so no pairing cancels it and a single A/B build cannot resolve a sub-2% effect.
# The gate therefore ignores any delta smaller than that row's own spread, however
# large it looks - java has been observed at +3.20% against a 3.21% spread, which
# is a coin landing heads.
#
# APPROXIMATE PER-ROW SPREAD at 5 draws: c 0.2-0.4%, python 1.3-2.2%,
# lua ~2.0%, kotlin ~3.1%, java 3.2-4.3%, ruby 4.2-4.8%. `c` is both the semantic
# control (self-contained IR, no js_* extern) and the tightest row, so read it
# first: if `c` moves, suspect the machine.
#
