# ARENA OCCUPANCY, per row - 2026-08-09, docs/todo.md 2.9.
#
# Columns 3 and 4 of every row below are `heap` and `collections` from
# MEC_GC_STATS, and bench.sh now prints them beside the instruction count and
# says STEPPED when the heap moves. They are EXACT counters, exempt from the
# layout lottery, and independent of the -exe path: measure once.
#
# HOW THE HEAP GROWS, which is the whole content of this section. The arena
# (languages/lib/runtime.c) is a per-SIZE-CLASS bump allocator. A block of 16n
# bytes comes from partition n, and a partition with no room mallocs a chunk of
# ~1 MiB - 1048576/bsize blocks of it. So:
#
#   1. The FIRST allocation in a size class costs a whole 1,048,576-byte chunk,
#      no matter that one 48-byte string goes into it. This is the only step
#      anyone here has ever actually hit.
#   2. A class already touched costs nothing until its chunk fills, and none of
#      them is close (below).
#   3. A block OVER 1024 bytes gets a chunk of exactly its own size - it steps
#      the heap by its own bytes and never by a chunk.
#
# AND `heap` IS AN ADDRESS-SPACE NUMBER, NOT A RESIDENT ONE. ar_block says so at
# its site: "the pages are only touched as the bump pointer reaches them, so an
# unused class costs address space and no resident memory." That is why ten
# near-empty 1 MiB chunks holding ~150 KB of live data is not the scandal the
# raw number looks like, and it is half of why a step is free. Read `heap` as
# "which size classes has this row touched", not as "how much memory is in use";
# `live` is the one that answers that.
#
# WHAT A STEP COSTS: NOTHING MEASURABLE - +0.20% over 45 paired builds, A slower
# in 26 of 45, which is a coin. This is the number the item most needed and it is
# the opposite of what the item assumed.
#
# The pair is a natural experiment that isolates the CHUNK from the module SIZE:
# two copies of mod.py differing by EIGHT characters, `_pad` of 72 chars (buffer
# 80, a class python does not use, so +1,048,560 heap) against `_pad` of 80 chars
# (buffer 96, a class it does use, so +0 heap). Everything else - the source, the
# module, the executed work, collections=3574 - is the same.

# WHY A MEDIAN OVER DRAWS AND NOT A NUMBER. A binary's instruction count depends on
# its CODE LAYOUT, and layout is perturbed by things that change no semantics. One

# so no pairing cancels it and a single A/B build cannot resolve a sub-2% effect.
# The gate therefore ignores any delta smaller than that row's own spread, however
# large it looks - java has been observed at +3.20% against a 3.21% spread, which
# is a coin landing heads.

# predicates into one-line delegations and cost python 41% and java 5.7% for four
# commits, while all seven CORRECTNESS gates stayed green - a slowdown is not a
# wrong answer. This file existed and nothing ran it. `tests/gates.sh --bench` now
# does. csharp is here because it shares rtjIsIntegral with java and only java's
# side was measured; a shared hot body needs ALL its callers in this file.
#
# js was ADDED BY HAND for the same reason go was, and the reason it had to exist
# is docs/todo.md 7.7: 673a8b1 cost ~20% on a yield*-heavy js workload (5.35 s ->
# 6.40 s over 300,000 steps) and NO GATE IN THIS PROJECT COULD SEE IT, because
# tests/bench/ had no js or typescript program at all. It does now.
#
# 1309000000 is the median over 21 DRAWS with the 2.5/2.6 round present, spread
# 5.33%. The same 21 draws in a clean `git archive` of the parent d473319, with
# only tests/bench/mod.js copied in, read 1,305,760,425 at a 6.58% spread - so the
# round is +0.25%, a fifth of the row's own spread and not a measurement. An
# earlier 15-draw pair read 1,306,580,684 base / 1,309,259,740, the same answer.
# The number here is rounded to seven significant figures ON PURPOSE: this row's
# spread is the widest in the file except ruby's, and quoting nine digits of a
# number that moves 5% between builds invites someone to read a 0.01% delta as
# real. `--record` will replace it with a full-precision one; that is fine, but do
# not then treat the extra digits as information.
#
# WHY THIS ROW IS SO WIDE. mod.js is the same 40,000-iteration `s + i % 7` loop
# every other row runs, but js reaches it through the handle-IR value model with
# BigInt wrappers in front of `+`, `%` and `===` (js_jsadd and friends), so the
# module is large and its layout is drawn from a correspondingly wide
# distribution. Read a js delta against the 5-6% spread, never against 2.5%.
#
# typescript has no row: mod.ts would compile the SAME loop through a grammar that
# shares layer 2 and the Go twin with js, so it would measure the same code twice
# and double the gate's runtime. If a change ever lands in only ONE of the two
# emitters, add it then.
#
# swift was ADDED BY HAND, and its absence was itself a finding: docs/todo.md 1.2
# had to close a defect whose fix puts js_swadoptdeep on a per-call path - the
# documented +10.3% charAt trap of a68e16d - and NO GATE IN THIS PROJECT LOADED
# languages/lib/swift-rt.ll AT ALL, because tests/bench/ had no swift program.
#
# 4516900000 is the median over 21 DRAWS with the 1.2 round present, spread 3.42%.
# This row is unusually REPRODUCIBLE for a handle-IR language - four separate
# 21-draw and 9-draw runs of the same tree read 4,516,802,998 / 4,516,803,640 /
# 4,516,805,038 / 4,516,809,798, agreeing to 0.0002% - so unlike java or ruby it
# CAN resolve an effect well below its own spread, and the three-way attribution
# below is real rather than a draw:
#
#   d473319 + only tests/bench/mod.swift        4,396,925,479   4,397,348,379
#   ... + the ADOPTION work of docs/todo.md 1.2 4,396,660,675   (-0.006%)
#   ... + Array.insert(_:at:)                   4,516,80x,xxx   (+2.73%)
#
# THE ADOPTION WORK COSTS NOTHING, and not by luck: the emitted module for
# tests/bench/mod.swift is md5-IDENTICAL between d473319 and this tree, which is an
# exact counter and settles it outright. The a68e16d trap was avoided by deciding
# the adoption AT EMIT TIME - the parameter gate is swAdoptNeeded, which asks
# whether any identifier token in the annotation text names a type that adopts, so
# an annotation with no adoptable leaf emits no call and mod.swift (which has no
# annotated parameter at all) emits exactly the IR it did. Gating on swTyIsDeep
# instead would have put a js_swadoptdeep call on every structurally annotated
# parameter in every program.
#
# THE WHOLE +2.73% IS Array.insert(_:at:), which mod.swift never calls: 197 lines
# of layer 2 that are dead on this program. That is the module-SIZE mechanism the
# python note above records (2,917 dead lines benched +4.53%), not a hot path -
# the arm sits inside js_swmcall's non-float branch, so no call on mod.swift's path
# even tests for it. It is the standing tax on any layer-2 addition, and it is here
# so the next person does not attribute it to the adoption work. Rounded to seven
# significant figures on purpose, as the js row is.
#
# go was ADDED BY HAND (not by --record, which would have deleted everything
# above): 844,097,409, the median over 9 draws, spread 2.36%. Measured with the
# go grammars of the commit that added it, whose emitted module for

# 1.7 notes what that cost: `a, b := xs[i], ys[j]` did not parse in either half

# 2026-08-08, docs/todo.md 7.7: THE LAST FIVE UNCOVERED LANGUAGES. Added BY HAND
# in a clean `git archive` tree of 1fd6293, at 21 DRAWS per row, twice.
#
# The item's list of eight was stale - mod.swift, mod.js, mod.cs and mod.go had
# landed since it was written. Re-derived from `ls tests/bench/` against the
# grammars that declare c.exePath, the truly uncovered real languages were SIX:
# dart, php, metajs, bash, batch and typescript. Five got a program; typescript
# did not, and why is below.
#
# dart        3903000000   spread 4.49%    (3,903,035,970 / 3,902,923,718)
# php         8064800000   spread 4.17%    (8,065,044,385 / 8,064,465,651)
# metajs       222990000   spread 0.76%      (223,018,012 /   222,968,468)
# bash          54970000   spread 0.32%       (54,982,321 /    54,955,779)
# batch         32880000   spread 0.56%       (32,892,473 /    32,869,792)
#
# The two 21-draw runs in the parentheses are independent runs of the SAME tree.
# They agree to 0.003% (dart), 0.007% (php), 0.02% (metajs), 0.05% (bash) and
# 0.07% (batch) - in every case one to three orders of magnitude inside the row's
# own spread, which is the check the todo header asks for. dart and php are
# rounded to seven significant figures for the reason the js row states: their
# spreads are 4%+ and nine digits of a number that moves 4% between builds invite
# someone to read a 0.01% delta as real. The three tight rows are rounded to five,
# which is still well below their spread.
#
# READ THE ROWS IN TWO FAMILIES. c, bash and batch compile to SELF-CONTAINED IR
# against a C runtime - unboxed machine words, no js_* extern, no MetaJS layer 2 -
# and the other twelve compile to HANDLE IR and link lib/<lang>-rt.ll. Only the
# second family can be moved by a floor or layer-2 change; the first is two orders
# of magnitude smaller by construction, and comparing across the line is
# meaningless. bash and batch are here anyway because bash-rt.c and batch-rt.c had
# NO performance gate of any kind and are the two runtimes whose arenas are never
# collected (manual 7.8) - a per-iteration allocation regression there is exactly
# what an instruction count sees.
#
# ===========================================================================
# 2026-08-08, docs/todo.md 2.2: THE TWO ARENA ROWS, RE-RECORDED BY HAND.
#
#   bash    54970000 -> 147629302   spread 0.09% over 9 draws  (+168.56%)
#   batch   32880000 ->  34199417   spread 0.23% over 9 draws    (+4.01%)
#
# Recorded in a clean `git archive 69d8e17` tree with ONLY languages/lib/bash-rt.c,
# languages/lib/batch-rt.c, their .ll and tests/bench/mod.{sh,bat} copied in - not
# with `--record`, which would have deleted every other row of this file and all
# of the text above it (see the NOTE at the top). The other thirteen rows are
# UNCHANGED and were not re-measured.
#
# THE PARENT WAS MEASURED FIRST, because this file's own history says a flagged
# row is as likely to be baseline drift as code. At 69d8e17, unmodified, 9 draws:
# batch 32,937,571 (+0.18% against the recorded baseline, inside its 0.26%
# spread) and bash 55,033,957 (+0.12%, inside its 0.76% spread). The baseline had
# not drifted, so both deltas below are the change.
#
# WHY bash MOVES 168% AND IS NOT A REGRESSION: mod.sh now runs 40,000 iterations
# instead of 10,000, the standard shape of every other program here. PER
# ITERATION it got CHEAPER, by a third: 55,033,957/10,000 = 5,503 instructions
# before, 147,629,302/40,000 = 3,691 after, -32.9%. The arena cost fell further,
# 204.8 -> 69.6 bytes an iteration, which is what let the count go back up - the
# 4 MiB ceiling was 20,750 iterations and is now 55,898 (bisected: 55,898 runs,
# 56,015 does not).
#
# WHY batch MOVES +4.01% AND IS ACCEPTED. It is a real increase, four times its
# own 0.23% spread, and it is the price of the bounds checks. Attributed by
# measuring an intermediate tree with the bounds checks and NONE of the cost
# reductions: 33,851,689, i.e. +2.77% against the parent. So the checks are
# +2.77% and the three allocation reductions add the remaining ~1.05% of
# instructions while removing 59% of the ALLOCATION (31.95 -> 13.1 bytes an
# iteration, ceiling 65,468 -> 160,351, and mod.bat's margin 1.6x -> 4.0x).
# A 4% instruction cost to turn `rt_bump` walking off the end of a 2 MiB array
# into a named diagnostic and a distinct exit code is a trade this file records
# rather than argues: counters are exact, and the counter says 4%.
#
# WHAT USED TO BE HERE, kept because it is the measurement that started this:
#
# AND IT PAID OFF ON THE FIRST RUN: the 40,000-iteration mod.sh SEGFAULTS. bash's
# `arena[4194304]` is 4 MiB, `rt_bump` has no bounds check and nothing is freed,
# and this loop costs ~202 bytes an iteration because `$(( ))` re-parses the
# accumulator's decimal text and rt_int2str writes a fresh arena string per
# assignment. Bisected: last count that runs ~20,750, first that does not ~20,781,
# and past it the binary exits 139 having printed nothing - the manual's "a
# crashing binary looks fast" trap, live, in the very first row measured. mod.sh
# therefore runs 10,000 iterations, a 2x margin, and says so at the top. batch's
# `AR[2097152]` is 2 MiB at ~32 bytes an iteration and its ceiling is ~65,468, so
# mod.bat keeps the standard 40,000 at a 1.6x margin. Neither ceiling was changed:
# languages/ was not this round's to touch, and both are recorded as findings.
# (Both findings were acted on on 2026-08-08 - see the re-record above. The
# ceilings themselves are UNCHANGED; what changed is that crossing one is now a
# diagnostic instead of a segfault, and that it takes 2.9x / 2.4x more work to
# reach one.)
#
# WHY THERE IS STILL NO mod.ts. typescript-to-llvm-ir.abnf links lib/js-rt.ll -
# the same layer 2 and the same Go twin as js - so mod.ts would run mod.js's code
# a second time and double the gate's runtime for it. The item counted typescript
# as an uncovered LAYER 2 and that is no longer true: js covers it. What remains
# uncovered is the typescript EMITTER's own codegen, and the standing decision
# (recorded above at the js row) is to add mod.ts the first time a change lands in
# one of the two emitters and not the other.
#
# WHAT THE NEW ROWS ARE WORTH. php is one of the three languages that need the
# __raw truthiness rule (manual 7.1), so its loop condition goes through layer 2
# every iteration; dart and swift share the bodies that used to live in
# lib/runtime-dartswift.metajs (folded into runtime.metajs on 2026-08-10), so those
# have two callers measured rather than one, which is the same argument that put
# csharp beside java. metajs is the substrate row: metajs-to-llvm-ir.abnf
# is the grammar every other language's layer 2 is compiled by, so a change there
# moves every handle-IR row in this file, and this row is the one that says so
# directly. It is also the tightest handle-IR row here at 0.76%, which makes it
# the most sensitive instrument in the file after `c`.
