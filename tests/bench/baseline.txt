# a `--paired OTHERTREE` mode that builds both checkouts to the same paths and
# reports a SIGN TEST over matched pairs. Reach for --paired whenever a delta is
# smaller than the row's own spread. It settled two questions this round, in
# OPPOSITE directions:

#           grows 464 bytes (+0.11%), which cannot produce +2.7%.
#
#   python  read +2.67% on medians and IS REAL - slower in 11 of 12 paired draws

# The two 21-draw runs in the parentheses are independent runs of the SAME tree.
# They agree to 0.003% (dart), 0.007% (php), 0.02% (metajs), 0.05% (bash) and

#
# READ THE ROWS IN TWO FAMILIES. c, bash and batch compile to SELF-CONTAINED IR
# against a C runtime - unboxed machine words, no js_* extern, no MetaJS layer 2 -
# and the other twelve compile to HANDLE IR and link lib/<lang>-rt.ll. Only the
# second family can be moved by a floor or layer-2 change; the first is two orders
# of magnitude smaller by construction, and comparing across the line is
# meaningless. bash and batch are here anyway because bash-rt.c and batch-rt.c had
# NO performance gate of any kind and are the two runtimes whose arenas are never
# collected (manual 7.8) - a per-iteration allocation regression there is exactly
# what an instruction count sees.
#
# AND IT PAID OFF ON THE FIRST RUN: the 40,000-iteration mod.sh SEGFAULTS. bash's
# `arena[4194304]` is 4 MiB, `rt_bump` has no bounds check and nothing is freed,
# and this loop costs ~202 bytes an iteration because `$(( ))` re-parses the
# accumulator's decimal text and rt_int2str writes a fresh arena string per
# assignment. Bisected: last count that runs ~20,750, first that does not ~20,781,
# and past it the binary exits 139 having printed nothing - the manual's "a
# crashing binary looks fast" trap, live, in the very first row measured. mod.sh
# therefore runs 10,000 iterations, a 2x margin, and says so at the top. batch's
# `AR[2097152]` is 2 MiB at ~32 bytes an iteration and its ceiling is ~65,468, so
# mod.bat keeps the standard 40,000 at a 1.6x margin. Neither ceiling was changed:
# languages/ was not this round's to touch, and both are recorded as findings.
#
# WHY THERE IS STILL NO mod.ts. typescript-to-llvm-ir.abnf links lib/js-rt.ll -
# the same layer 2 and the same Go twin as js - so mod.ts would run mod.js's code
# a second time and double the gate's runtime for it. The item counted typescript
# as an uncovered LAYER 2 and that is no longer true: js covers it. What remains
# uncovered is the typescript EMITTER's own codegen, and the standing decision
# (recorded above at the js row) is to add mod.ts the first time a change lands in
# one of the two emitters and not the other.
#
# WHAT THE NEW ROWS ARE WORTH. php is one of the three languages that need the
# __raw truthiness rule (manual 7.1), so its loop condition goes through layer 2
# every iteration; dart shares lib/runtime-dartswift.metajs with swift, so that
# file now has two callers measured rather than one, which is the same argument
# that put csharp beside java. metajs is the substrate row: metajs-to-llvm-ir.abnf
# is the grammar every other language's layer 2 is compiled by, so a change there
# moves every handle-IR row in this file, and this row is the one that says so
# directly. It is also the tightest handle-IR row here at 0.76%, which makes it
# the most sensitive instrument in the file after `c`.
